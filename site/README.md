# Ghost 本地展示网页

用户最新要求只在本机使用，不发布到 Cloudflare 或其他公网服务。原 Cloudflare Pages 项目 `exo-ghost` 已删除。

网页由 `index.html`、`styles.css`、`app.js`、`live.js`、`control.js` 和 `assets/`、`data/`、`vendor/` 组成，无构建步骤。3D 页可读取真机实时流、播放真实桌面记录，并在安全条件满足后手动请求动力辅助或健身阻力。
`index.html` 的模块入口及其本地依赖带同一个版本参数；修改页面脚本后同步更新该参数，避免 Chrome 沿用旧缓存。

3D 控制区下方的长篇模型与数据说明已从页面移除。素材授权、数据来源、视觉估算及真机验证边界留在本说明、`docs/FEATURES.md` 和 `model-sources/`；使用时必要的连接状态、安全档和控制反馈仍在页面显示。

3D 区域采用操作语言：按钮显示“隐藏/显示人物”“重置站姿”“转身同步”，设备重连显示“正在连接设备”；运动卡片和当前模式使用功能与强度名称，不向用户展示原始增益、视觉基准或模型加载细节。历史记录与实时设备状态仍分开显示，设备保护触发时仍提示人工恢复。页面文案变化不影响原有安全门槛或控制命令。

3D 页显示最近一条运动建议及来源。本地服务从 Git 忽略的 `data/product/evomap_gateway.key`、`EVOMAP_API_KEY_FILE` 指定的文件或 `EVOMAP_API_KEY` 环境变量读取 Gateway key；网页不会接收密钥。默认只建议；显式启动桌面档 `--autopilot` 后，模型选出的模式还须通过最新本地状态复核才可执行，且最多 0.5 N·m。穿戴档不能启动自动控制。没有 key 时使用本地规则。模型调用可能持续数秒，页面在设备状态仍新鲜时将最近建议保留 20 秒。

## 本地启动

在仓库根目录运行：

```sh
python3 -m http.server 8788 --bind 127.0.0.1 --directory site
```

在 Chrome 打开 `http://127.0.0.1:8788/`。不要直接用 `file://` 打开；浏览器模块和回放数据需要 HTTP。`--bind 127.0.0.1` 保证服务只在本机可访问。检查桌面、移动端导航、图片、3D 加载和回放按钮。

## 更新流程

每次功能变更，同步 `docs/FEATURES.md`、`CHANGELOG.md` 和本网页，按仓库 `AGENTS.md` 进行本机验证。网页不直接打开串口，不读取私人数据库。运动模式只经现有本机 WebSocket 控制服务；需要明确的 `body=real`、`profile=table|wearing`、`ARMED`、新鲜状态和传感器帧。常驻桌面档勾选框已移除；首次点击运动按钮时，页面按服务报告的安全档请求现场确认，确认后再检查就绪状态并发送。桌面档只供无人穿戴测试；穿戴测试须用 `--profile wearing` 启动服务并完成穿戴前检查。断线、失效或安全档变化会撤销网页确认，重启后不自动开启模式。页面只保留“松劲”按钮，连接存在时可发送 `zero`；底层急停机制不受页面按钮移除影响。

3D 页“左右腿独立调节”可分别为每侧选择松劲、动力辅助或健身阻力：应用左腿或右腿时保留另一侧服务当前报告的模式，同时应用则一次提交两侧选择。助力增益最高 0.1、阻力增益最高 0.5，单侧力矩上限 0.5 N·m；服务继续执行死区、低通、安全渐弱、缓升、穿戴档限速及急停。控件只在状态包含 `capabilities.bilateral_modes=true` 且上述控制门槛全部满足时开放。旧服务可继续用现有双腿按钮；若仅支持 `split_resist`，旧版左右独立阻力入口仍显示。新代码尚未在真实设备施力验证，不能将页面出现按钮等同于真机可用。

左右腿卡片不显示控制服务版本提示；服务能力不足或设备未就绪时，应用按钮保持禁用。该显示调整不改变命令门槛。

## 实时视图

页面打开时自动加载 3D 模型并默认选择“实时数据”；本机设备服务送来新鲜有效数据时，角度、角速度和指令力矩自动更新，外骨骼与人体随双髋角度变化。设备离线、腿板失效、仿真来源或超过 1.5 秒没有新帧时，读数留空，模型停止更新；WebSocket 每秒尝试重连。操作员急停锁存时页面明确显示等待人工恢复，绝不自动重新武装；曲线控制台在确认现场安全后提供手动入口。旧控制服务未报告 `body` 来源时，页面会标明“来源未标记”。“历史记录”模式单独播放桌面标定记录，不代表当前设备正在运动。真机动作联动和断电重启后的完整现场恢复仍需现场复核。

3D 直立视觉基准固定在 `data/twin-config.json` 的 `upright`：左髋 17.30°、右髋 −10.34°。这组值来自用户确认直立时的 130 帧真机数据中位数，两侧角速度中位数均为 0。页面刷新和串口重连始终使用同一组基准，再以实时角度差驱动左右腿；“重置站姿”按钮也恢复到这组值。原始角度曲线和传感器数据不改；视觉基准不作为电机零位、传感器或机械几何的绝对标定，也不向设备发指令。

真机前后迈腿的视觉方向由 `data/twin-config.json` 的 `sign` 控制。用户指出旧版在实体前迈时模型后摆，现已将左右视觉符号反转；这不改变外骨骼的电机方向。设备恢复实时连接后仍需分别前迈左右腿进行现场复核。

人体模型旋转后，解剖左髋位于 `+Z`。外骨骼模型的该侧网格在原素材配置中叫 `right`，所以 `app.js` 将实体左传感器映射到人体左髋和外骨骼 `+Z` 网格，右传感器映射到另一侧。页面读数仍保留实体左、右通道名称。

“转身同步”使用腰部 IMU 的短时 yaw 增量，并要求陀螺仪有明显实际转动，避免静止时 yaw 漂移让模型自行旋转；旋转是相对朝向，不代表绝对罗盘方向。可关闭此项，或用“重置站姿”从当前朝向重新开始跟随。页面已有鼠标/触控拖动视角，与实体转身相互独立。当前数据不含膝、足触地和空间位置，不能还原真实脚步或前进距离。

实时双髋角度同时驱动外骨骼和半透明人体的左右腿。`site/motion.js` 在人体向前抬腿时根据髋角与角速度估算屈膝角，落腿时平滑伸膝；`site/app.js` 按白膜骨骼和脚尖方向让小腿向身后弯曲，避免反向折向脚尖。此视觉动作只驱动白膜人体小腿骨骼，不改变外骨骼、电机控制或实测数值。`site/motion.js` 仅在双侧持续出现足够幅度的交替摆动时显示“检测到交替摆腿”；静止、单腿摆动及断流不会显示此状态。这是髋关节模式提示，不是行走确认。当前没有真实穿戴步行记录，也没有膝、脚部或空间位移传感器；估算屈膝不代表实测膝角，模型也不会自行向前移动。

外骨骼腰带和双侧腿部固定环的视觉贴合参数位于 `data/twin-config.json` 的 `fit`。页面启动 3D 视图时收紧腰带与固定环，以白膜人体可见的膝部轮廓为准，将两侧绑腿下缘抬到膝盖上方约两指；腿部支撑杆下段平滑移到新环位，双侧组件在髋部运动时仍一起转动。配置读取不使用浏览器缓存。当前白膜网格的可见膝部与绑骨关节点不完全重合，不能从关节点坐标直接推断外观间距；这些参数只是视觉校正，不代表实体绑带已收紧或适合穿戴。

## 素材与隐私

- `assets/hypershell-*.webp`：依据用户确认获官方许可的 Hypershell X Max S 图片优化生成；原图 URL 和许可说明见 `feat/auto-reconnect-GPT` 分支的 `dashboard/assets/README.md`。
- `assets/exoskeleton.glb`：同分支 Tripo 生成的视觉模型，不是工程 CAD 或安全模型。
- `assets/human-tripo-rigged.glb`：Tripo 生成并自动绑骨的白膜人体，参考已确认获准使用的官网穿戴照片的比例，但没有真实面孔，也不是官方模型。网页去除贴图、调整透明度与尺寸，修正前后穿戴朝向及左右髋对应，再以实测双髋角度驱动腿部；详细来源、生成任务及限制见 `assets/HUMAN-LICENSE.md` 与 `../model-sources/README.md`。
- `data/twin-replay.json`：真实设备桌面标定记录的抽样回放，并非当前在线数据。
- `vendor/`：Three.js 与加载器本地文件，许可证见 `vendor/THREE-LICENSE`。
- 不把 `data/` 中的私人会话记录、密钥、实时控制地址或操作命令复制到网页。
