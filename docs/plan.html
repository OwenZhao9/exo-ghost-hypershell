02赛道题目与评审要点原题为文档事实 · 拆解表为我的建议

出题人 = 评委 = Hypershell。题目要求六件事：身份、真实任务、工具调用、异常处理、经验继承、可验证的交付。外骨骼是他们明说"鼓励使用"的义体。

原题

「Hypershell」向你提问：给 Ghost 一个身份，再交给它一项真实任务。个人助理、企业工作流、研究、教育、内容与城市服务，都有等待解决的具体问题。让 Agent 搜索、继承并调用网络中已经验证的经验，使用工具、处理异常，完成任务。你需要展示它交付了什么，以及这些结果如何被验证。

选赛道指引原文："致敬攻壳机动队，让 ghost 登陆义体外骨骼。" Hypershell 鼓励但不强制使用其外骨骼平台，并提供样机与技术文档。

题目拆解 → 我们的对应

题目要求方案里怎么体现
身份住在外骨骼里的教练，有名字、声音、对每个穿戴者的记忆
真实任务带穿戴者完成一段 2–3 分钟目标行走（省力 / 练腿 / 对称），交付报告
工具调用set_policy、get_features、speak、ask_user、evomap_search、evomap_store
异常处理串口断开、踉跄、电量低、用户说停，各有明确动作，展位上主动演一个
经验继承开始前查 EvoMap 先验参数，结束后写回；第二个穿戴者校准更快
交付与验证交付单：每条结论对应一段传感器数据；独立验证器签字

03外骨骼平台与串口协议文档事实 · Hypershell 技术文档 + 协议附件

没有档位，只有裸力矩。设备给 200 Hz 的 15 通道数据流，我们以 200 Hz 回发左右力矩；100 ms 不续发自动清零。控制器必须自己写，安全闸是第一优先级。

平台

项目内容
型号Hypershell X MaxS 髋关节助行外骨骼
固件2.9.99.1（黑客松专用）
开放能力机身传感器数据流 + 电机力矩控制接口
接口USB CDC 串口，与电脑上位机通信；macOS 免驱，设备名 /dev/cu.usbmodem*
文档技术支持文档：https://autogame.feishu.cn/docx/L49jdUGenooxdxx3ci9cB94Fnle
协议：附件《深圳黑客松2026串口协议.docx》（3 页，552 KB）；hypershell.feishu.cn 的在线版无权限
内部结构（仅供理解）左腿 = 主板 CAN ID 21，右腿 = 从板 CAN ID 20；左右力矩走广播 CAN_SET_ETE_FORCE，互相独立；力矩环为电流随动 iq = torque / 比例系数

串口参数与限制

项目规定
物理层USB CDC，3,000,000 baud，8N1，一行一条命令，\n 结尾（\r\n 也可）
数据流频率固定 200 Hz（IMU / 编码器有效更新约 200 Hz）
力矩下发频率建议 200 Hz，允许 10–500 Hz
看门狗100 ms 未续发 T，力矩自动清零
力矩范围±7.5 Nm，固件限幅
单位力矩 Nm；角度 °；角速度 °/s；陀螺仪 °/s；加速度 g；气压 kPa
上电顺序插 USB 后先开机进入工作态，再发 ENABLE；此固件插 Type-C 不进充电态

命令

发送应答说明
PINGPONG连通性
VERSIONOK,VERSION,2.9.99.1固件版本
ENABLEOK,ENABLE使能力矩并开始 200 Hz 数据流
DISABLEOK,DISABLE力矩清零并停止数据流
T,<left>,<right>OK,T,<left>,<right>左右解耦力矩，Nm，范围 ±7.5

错误应答：未 ENABLE 时发 T → ERR,NOT_ENABLED；格式错误 → ERR,T_FORMAT；未知命令 → ERR,UNKNOWN。

数据流帧（ENABLE 后固定 200 Hz）

S:<ms>,<pitch>,<roll>,<yaw>,<gx>,<gy>,<gz>,<ax>,<ay>,<az>,<kPa>,<Ldeg>,<Rdeg>,<Ldps>,<Rdps>
字段含义单位
ms主板时间ms
pitch, roll, yaw穿戴系欧拉角°
gx, gy, gz腰部陀螺仪角速度°/s
ax, ay, az腰部线性加速度g
kPa气压kPa
Ldeg, Rdeg左右髋关节输出轴角度°
Ldps, Rdps左右髋关节输出轴角速度°/s

最小流程（协议原文）

PING
ENABLE
T,1.5,-1.5
T,1.5,-1.5
...

协议没有写明角度的正方向（屈 / 伸）和左右是否镜像。这决定所有控制器的符号，必须在验机时（见 08）自己测出来。

04VOFA+：是什么、怎么用前两表为文档事实 · 用法与插件结论为我的判断

VOFA+ 是 Hypershell 推荐的串口调试"上位机"，本质是串口助手 + 实时示波器。我们只用它做前十分钟的验机和零代码兜底可视化，它不是控制器，插件也不用碰。

基本信息

项目内容
是什么国内开发者（固特加）2018 年起做的调试软件，原名"伏特加"；设备通过串口/网口吐数据，它解析后画曲线，也能点按钮给设备发命令
版本 / 平台1.3.10；Windows、Mac Universal（dmg）、Linux；免费下载（尚未下载）
三个核心概念数据：解析出的通道（外骨骼 15 个字段 = I0–I14）；命令：预写字符串绑到按钮；参数：命令里的 %f 占位符绑到滑条
协议引擎FireWater（逗号分隔文本，外骨骼用这个）、JustFloat（二进制浮点）、RawData（原样显示）
FireWater 格式"<any>:ch0,ch1,...,chN\n"，换行是帧结束符；外骨骼的 S: 帧就是标准 FireWater 帧，"S:" 是固件的约定不是 VOFA+ 的要求

在本项目中的用法

用途操作结论
验机串口 3000000 → 协议 FireWater → 发 ENABLE → 右栏出现 I0–I14 → 把 I11/I12（Ldeg/Rdeg）拖进波形图、点 Auto → 手摆支架看方向比自己写解析快，十分钟内完成
发单条命令左栏"命令"Str 模式绑按钮：PING\n、ENABLE\n、DISABLE\n可用
手动出力滑条绑 T,%f,0\n只在拖动时发，无周期续发，100 ms 后被看门狗清零，只能看到"抖一下"——正好用来验证看门狗
姿态可视化Cube 控件绑 pitch/roll/yaw展位零代码兜底
当控制器—不行，没有 200 Hz 定时发送能力

插件商店结论

共 24 个，最新更新 2021 年初，之后停更。数据引擎就是自带三个；控件是仪表盘、旋钮、摇杆、切换按钮之类的装饰件；"命令"类为空，没有任何周期发送插件；皮肤 8 个。自定义插件只能 C++ 编译。不值得投入任何时间。

05方案：Ghost Coach（塔奇克马教练）我的建议

一个有身份的 Agent 住进外骨骼：读步态遥测，判断地形与状态，选择控制策略并解释为什么，带穿戴者完成一段目标行走，交付一份每条结论都能回溯到传感器数据的报告。

要素

要素设计
身份教练人格（致敬塔奇克马，组委会打卡墙就是它），有名字、有声音，记住每个穿戴者的身高体重、目标、上次表现
真实任务评委口头给目标：「让他上楼省点力」/「练腿，加阻力」/「左腿刚恢复，帮他走对称」→ 带穿戴者走 2–3 分钟 → 交报告
感知200 Hz 原始流 → 每秒特征摘要：步频、步幅代理（髋活动度）、左右对称指数、坡度（pitch）、爬升（kPa 趋势）、疲劳代理（步频下降 + 活动度缩小）
决策每 5–10 秒重评估，通过 set_policy(策略, 增益) 下发；每次变更语音说一句理由
异常处理串口断开 → 力矩自动清零、切手机 IMU 继续记录；角速度/加速度突变（踉跄）→ 桥接层直接清零，不经过 LLM；电量低 → 缩短计划；用户说"累了 / 停" → 立即停
经验继承开始前 evomap_search（"70 kg、上楼、resist 0.5 效果"）作为先验；结束后 evomap_store（画像、地形、参数、结果）；大屏标注"继承自 N 条经验"
交付与验证交付单：目标、决策时间线（时间戳 + 理由）、指标；每条结论点开即对应数据段曲线；独立验证器（规则校验 + 第二个模型复核）签字

交付单指标（全部可从数据流算出）

指标算法
步数、步频髋角度峰值检测（scipy.signal.find_peaks）
左右对称指数左右活动度（ROM）和步时的对称比
爬升高度气压趋势换算
设备做功 J∫ τ·ω dt，τ 是我们下发的力矩，ω 是测到的角速度（°/s 转 rad/s）
对照同一人、同一段楼梯：固定策略 vs Ghost 自适应，比步频和做功

给评委的一句话

今天这台设备是"有几个模式的电机"；装上 Ghost 之后它认识你、随路况和状态调整、会解释自己，而且每个人的经验都回流给下一个穿戴者。

06系统架构、控制策略与安全闸我的建议 · 仅力矩上限与看门狗来自协议

LLM 只做策略层，不进实时环。控制器在本地以 200 Hz 跑纯规则；桥接层的安全闸独立于一切上层逻辑。
注意：所有代码都运行在电脑上，通过 USB 串口控制设备；不向外骨骼烧录任何程序，固件 2.9.99.1 由 Hypershell 固定。

分层

外骨骼 ⇄ USB 串口 3 Mbps
   │
[设备桥 bridge]     读 S: 帧、解析、落 CSV；200 Hz 续发 T；PING/ENABLE/DISABLE；
                    安全闸；回放模式（从 CSV 喂数据，接口与真机一致）
   │
[控制器 controller] 200 Hz 纯规则：策略 × 增益 → 左右力矩；步态特征提取
   │  WebSocket：每 1 s 一份特征摘要 ↑ / 策略变更指令 ↓
[Agent 运行时]      身份 + 记忆、规划、工具调用、异常策略、语音 ASR/TTS
   │
[验证器 + 交付单]   [仪表盘] 曲线、决策日志、急停按钮

三种控制策略（Agent 可选策略与增益，增益有硬上限）

策略公式用途安全说明
zeroτ = 0透明模式，采基线—
resist(c)τ = −c · ω粘性阻尼，"练腿"天然稳定，最安全；走路时 ω ≈ 2–4 rad/s，c = 0.5 即 1–2 Nm
assist(c)τ = +c · ω顺着运动方向推，"省力"本质负阻尼，会放大动作：c 从 0.2 起、加低通、加死区、上限 2 Nm；有余力再做按步态相位打脉冲的版本

安全闸（桥接层，不经过 LLM）

  1. 软件限幅：演示阶段 ±2 Nm（固件 ±7.5 Nm 只是最后一道）
  2. 斜坡：每 50 ms 最多变化 0.2 Nm
  3. 踉跄检测：|加速度| 或 roll/pitch 突变 → 立即清零并 DISABLE
  4. 键盘一键 DISABLE；桌上一个物理急停 = 拔 USB（100 ms 内固件自动归零）
  5. 串口异常、进程退出（atexit）都发 DISABLE
  6. 拆分进程：控制环与 LLM 调用不在同一进程，网络卡顿不影响续发

08上电验机清单我的建议

前 30 分钟按顺序做，全部通过之前不穿在人身上。

  1. 不穿在身上，设备放桌上、腿部支架能自由摆动；接数据线，确认出现 /dev/cu.usbmodem*
  2. PING → PONG，VERSION → 2.9.99.1；ENABLE 后确认 S: 帧稳定 200 Hz；录 10 秒静止数据看噪声和零位
  3. 手动摆动左右支架，记录 Ldeg/Rdeg 的正方向是屈还是伸、两腿是否镜像
  4. 持续续发 T,1.0,0 一秒，看左腿往哪边动、Ldeg 怎么变；再 T,0,1.0 看右腿；记下符号约定
  5. 验证看门狗：停发 T，确认 100 ms 内力矩消失
  6. 以上全通过 → 穿上人 → 从 resist(0.3) 开始，再试 assist(0.2)

第 2、3 步可以直接在 VOFA+ 里做；第 4、5 步需要我们自己的 hold 工具（VOFA+ 不能续发）。

11待确认问题（问 Hypershell）我的建议

协议 docx 已经回答了接口形态、遥测字段、控制方式；剩下的都是"人穿着时"的问题，Workshop 和导师巡场时问。

  1. Ldeg/Rdeg 的正方向（屈为正还是伸为正），左右是否镜像（可自测，确认更快）
  2. 人穿着时他们建议的力矩上限和斜坡；我们计划演示阶段 ±2 Nm
  3. 他们内部的助力是按步态相位还是速度随动；+c·ω 这种负阻尼会不会引发振荡
  4. 持续出力下电池能撑多久；能否边用边充（协议说 Type-C 不进充电态）
  5. 样机能否留到 Day 4 展位；有没有备用机
  6. 官方 App 蓝牙同时连着会不会抢控制
  7. 展位评审时他们的工程师会不会在场，能不能提前看一眼我们的控制器
  8. EvoMap：经验检索 / 写入接口长什么样，模型 API 是否 OpenAI 兼容

12硬件与物料我的建议

最常见的"设备没反应"是充电线没数据线。

  • 能传数据的 USB-C 线 × 2
  • 外骨骼电池单独充；展位备一块满电的
  • USB hub（Mac 口不够时）
  • 台阶箱或提前踩点场地楼梯
  • RJ45 网线转接口（现场有线网）
  • 打印物料：一页架构图 + 一页交付单样例 + 二维码（GitHub 仓库）
  • Day 4 前把官网提交项逐一核对：介绍文档、GitHub 链接可访问、全员信息、赛道
